# 原文を残す説明の訂正

2026-09-08 採用。移行中のパラメーターのラベル・本文を訂正する手順です。旧フィールドを削除する段階とは分けます。

## 保存先と表示

`parameter[].documentation` に公開用の `value`（見出しの値の説明）と `description`（HTML 本文）を記述します。両方ではなく片方だけでも使えます。元の `parameter[].value` / `description` は原位置に保持し、指定しなかった項目は従来どおり表示します。

```json
{
  "parameter": "X",
  "value": ["水平方向乗算速度"],
  "description": "<p>訂正前の説明はここに残します。</p>",
  "documentation": {
    "value": ["水平方向に加える速度"],
    "description": "<p>実行者自身の水平方向の速度に加える量を指定します。</p>",
    "evidence": {
      "status": "confirmed",
      "basis": ["official_document"],
      "source_refs": ["veladd-local-1.0"],
      "comment": "資料の記載と照合して訂正。実機テストではない。"
    }
  }
}
```

この例の出典 ID は、同じ文書の `quote` に定義する必要があります。実際の記録は `src/content/state-controllers/VelAdd.json` / `VelSet.json` を参照してください。

- `documentation` は公開文の保存先です。未検証の仮説、調査途中の候補、公開不要の結果は従来どおり `notes.kind: research` / `visibility: internal` に残します。検証状態の変更だけで本文へ昇格しません。
- `documentation.evidence` は任意の内部記録です。訂正時には根拠と理由を残してください。検証状態・出典 ID の規則は既存の `evidence` と共通です。HTML に証拠や訂正過程を併記しません。
- 空オブジェクト、空ラベル配列、空文字の本文は入力エラーです。未知のキーも拒否します。パラメーター名、型、既定値、読み込み順、適用環境をこのオブジェクトで上書きできません。
- 有効な表示データを作る際に、旧形式の値へ公開文を重ねます。JSON 原本は変更せず、詳細ページと State 一覧は同じ処理を通ります。
- 共通パラメーターを使う場合は、それぞれの公開文を解決してから固有定義を優先して統合します。Trigger の旧引数に記録がある場合も利用できますが、対応する `arguments[].description` の明示指定が優先です。
- 既に `documentation` がある項目の追加訂正は、その公開文を編集します。最初の旧文はそのまま保持し、公開文の変更履歴は Git、判断の根拠は `evidence` / 内部注記へ残します。上書きオブジェクトを何段も追加しません。

## 訂正の手順

1. 旧文と資料・実測・管理者確認を照合し、表記ミスと未確定の仕様差を区別します。矛盾する資料や未確認値は消しません。
2. 対象が保存済みの比較基準に含まれることを確認します。未移行の対象は [小分け移行](BATCH_MIGRATION.md) で先に比較基準を保存します。検査を通すための基準の更新は禁止です。
3. 訂正済みの公開文を `documentation` に記入します。説明の具体的な値・向き・省略条件を抽象化して落とさず、編集理由と出典を内部に残します。
4. `mugen:validate` / `mugen:test` / `build` / `mugen:check-html` を実行します。旧文の保存、公開文、一覧、CNS コピー出力、読み込み順、非公開記録の非表示を確認します。ブラウザで確認できない場合はその制約を記録します。

移行済み JSON への説明の訂正は通常の個別編集です。適用済みバッチを再実行したり、その追加計画や比較基準を書き換えたりしません。
