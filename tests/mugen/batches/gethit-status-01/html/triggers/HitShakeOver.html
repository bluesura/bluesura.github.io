HitShakeOver

ヒット情報 > ヒットシェイクの終了判定 | 実装されたバージョン: 2002.04.14 | 対象: 使用者自身
引数 仕様・注意点 使用例 引用記事

プレイヤーが被弾ステート中に、ヒットシェイク（その場で揺れながら停止する時間）が終了しているかを返します。

  • 0: ヒットシェイク中
  • 1: ヒットシェイクが終了

ヒットシェイクは通常、攻撃側のHitDefで指定するPauseTimeの2番目の値（被弾側を停止させるフレーム数）に対応します。

やられステートを自作する場合は、HitShakeOverが1になったタイミングで速度付与（VelSet等）や演出処理を開始し、その後はHitOverで硬直終了（hittime満了）を判定して次のステートへ移行する、という使い分けが一般的です。

関連するトリガー： HitOver , GetHitVar(hitshaketime) , GetHitVar(hittime) , HitPauseTime

なし

仕様・バグ・エラー・変更点

  • MUGEN 1.0

    トリガー自体の仕様は1.0でも同様です。
    なお、1.0ではHitDefのPauseTime（P1側）の「1フレーム早く切れる」不具合が修正され、旧版（2002.04.14）互換のための補正が入ります。HitPauseTime等と併用してタイミングを厳密に揃える場合は、旧版との差分に注意してください。

  • IKEMEN GO

    MUGEN互換の判定として扱われ、Luaではhitshakeover()としても参照できます。

Q＆A(よくある質問)

HitPauseTime と HitShakeOver の違いは？

HitPauseTimeは攻撃側（自分の攻撃が当たった側）のヒットポーズ残り時間を返します。初期値はHitDefのPauseTimeの1番目の値です。
HitShakeOverは被弾側のヒットシェイク（その場で揺れる停止）終了判定で、被弾ステート中でのみ意味があります。

コードサンプル

ヒットシェイク中だけ処理する

被弾中で、まだ揺れが終わっていない間だけ発火します。

  • Trigger1 = MoveType = H
  • Trigger1 = HitShakeOver = 0

ヒットシェイク終了後にカスタム処理へ移行する

揺れが終わった後から、独自のやられ演出や押し戻し処理を開始する例です。

  • [State 5000, ChangeState]
  • Type = ChangeState
  • TriggerAll = MoveType = H
  • Trigger1 = HitShakeOver
  • Value = 5010
