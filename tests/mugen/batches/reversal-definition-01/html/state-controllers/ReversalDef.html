設定できるのはHitDefのパラメータのうちpausetime, sparkno, sparkxy, hitsound, p1stateno, p2statenoと、以下の必須パラメータです。

当て身投げ、弾き、回避技などに。

Reversal.Attr = 反撃属性1, 反撃属性2, ...

省略不可
型文字列, 文字列, ...
省略時?, ?, ...

どのような攻撃を受けたときに反撃するかを文字で指定。

反撃属性1には、「S」「C」「A」(順に立ち、屈み、空中)のいずれかを指定します。

反撃属性2には、「N」「S」「H」「A」（順に通常、必殺、超必殺、すべて）と、「A」「T」「P」（同じく攻撃、投げ、飛び道具）を組み合わせて指定します。

例えば、reversal.attr = SA,NA,SAとした場合は、立ち又は空中で出す通常攻撃、必殺技に対し、反撃します。

Attr = 反撃属性1, 反撃属性2, ...

型文字列, 文字列, ...
省略時?, ?, ...

攻撃の属性を指定します。

属性1には、「S」「C」「A」(順に立ち、屈み、空中)のいずれかを指定します。

属性2には、「N」「S」「H」「A」（順に通常、必殺、超必殺、すべて）と、「A」「T」「P」（同じく攻撃、投げ、飛び道具）を組み合わせて指定します。

例えば立ちパンチなどならAttr = S,NA、空中で飛び道具を出す超必殺技ならAttr = A,HP と記述します。

空中判定になる地上攻撃(リープアタック等)は、空中扱いにしましょう。ただし、AirやOffsetで見た目のみ浮いている場合は、地上扱いでもかまいません。とりあえず、statetypeと同じにしておけば、問題ないでしょう。

P2StateNo = ヒット時相手に参照させるステート番号

型整数
省略時-1 ;無効

攻撃がヒットした場合に、相手に参照させるステートの番号を指定します。これを指定した場合、HitOverrideを仕込んだ相手(Helper等)に攻撃が当たらなくなります。

P2StateNo=-1とすると、P2GetP1State=1の効果のみになる。（P2GetP1State=0が指定されている場合はP2GetP1Stateが優先されるためP2GetP1State=0となる。）なお、この際に5000番台に移動するのはGround.Type、Air.TypeがNormal(頭文字がN）以外の場合である。

投げに使ってもProjectile等と相打ちした時に致命的な不具合が生じることがあるので、できれば全く使わない方が良いです。

といいたいところですが、代わりに使うことになるTargetStateも扱いが難しいので、不具合を承知で使うのも止むを得ないかもしれません。

Ground.HitTime = ヒット時間

相手が地上にいる間のみ有効です。

Ground.SlideTime = ヒットバック時間

型整数
省略時0

相手が攻撃を受けて後ずさる時間です。この時間が経過すると、ブレーキがかかります。ただし、やられステートのphysicsがSやCになっているため、ヒットバックは摩擦によっても停止します。よって、よろけやられのような、ゆっくりとしたヒットバックは、HitDefでは再現できません。

0の場合、強烈なブレーキがかかるためパラメータの省略は推奨できません。

相手が地上で攻撃を受けて移動する速度です。yに負数を指定すると、宙に浮きます。地上にいる場合、摩擦の影響を受けます。

Ground.CornerPush.VelOff = 地上コーナープッシュ速度

型浮動小数点数
省略時; AttrがAの場合は0、それ以外の場合は、1.3*guard.velocity

画面端で地上の相手に攻撃を加えたときに、押し戻される速度を指定します。値が大きくなるほど、画面端から遠くに押し戻されます。

相手の移動距離とは無関係で、相手のshaketimeではなく、自分のpausetimeが0になった瞬間に速度がかかります。

Air.HitTime = 空中でのヒット時間

型整数
省略時20

相手が空中で攻撃を受けて行動不能になる時間です。

この時間を過ぎると、相手はコントロールを取り戻します。この時、空中くらい/ふっとびアニメ(5035番)はAirに依存するため、5035番のアニメが終わり見た目が立ち直っていても、行動不能な時間内なら行動不能。行動不能な時間が経過していれば、5035番のアニメ中で見た目がのけぞっていても行動可能です。

Persistent = 実行頻度（トリガー成立回数の間引き）

型整数
省略時1
最小値0
最大値128

Persistent は、このステートコントローラーが「実行可能（発火）」になった回数を基準に、実行頻度を間引くための共通パラメーターです。

まず「トリガー成立（= 実行可能）」の定義は次のとおりです。

  • triggerall は共通の前提条件（AND）です。triggerall が偽のフレームでは、trigger1 以降が成立していても発火しません。
  • trigger1 / trigger2 / trigger3 ... は番号ごとにグループで評価されます。
    • 同じ番号（例：trigger1 が複数行）は AND（全部真ならその番号グループが真）。
    • 番号が違うグループ同士（trigger1 と trigger2 など）は OR（どれか1つのグループが真なら発火）。

この「発火（トリガー成立）」が起きた回数に対して、Persistent は次のように動作します。

  • 1（既定）: 発火するたびに毎回実行します。
  • 0: そのステートにいる間は最初の1回だけ実行します（ステートを離れて戻るとカウントはリセットされ、再び1回実行可能になります）。
  • N（2以上）: 発火したN回に1回だけ実行します。
    例：発火が毎フレーム続く（= 毎フレーム発火条件が真）なら、見かけ上はNフレームに1回の実行になります。発火が断続的な場合は、実行間隔も断続的になります（“フレーム”ではなく“発火回数”で数えるため）。

値に指定できるのは整数定数のみです（var/fvar/sysvar を含む式は不可）。

注意: 一部の解析記事では、エンジン内部でステート内のステートコントローラーごとに「Persistent用のカウンタ」が確保され、最大512個相当まで管理される、と説明されています。極端に大量のステートコントローラーを1つのステートに詰め込む設計は、可読性だけでなく実装上の制約にも触れやすいため、常時処理が肥大化している場合は分割・整理を推奨します。

Q＆A(よくある質問)

Helperが分身して消えない。

「Helper」側が適正に「HitOverride」を使っていない場合や、HitOverride」を使っていても、「Helper」が直に「HitDef」を出しており、 なおかつ相手側が適切にAttrを設定していない「ReversalDef」を使用した場合などに起こってしまう。「Helper」に行わせていた処理次第で、ひどい不具合を引き起こす可能性があります。

  • 「Helper」には 必ず 「HitOverride」を使わせる。
  • 「Helper」には なるべく 直接「HitDef」を持たせない。
  • 「ReversalDef」で「P2StateNo」を使用するときは 必ずAttrを適切に設定する。
  • 「IsHelper」をトリガーにして、「DestroySelf」や「ChangeState」を記述する。
