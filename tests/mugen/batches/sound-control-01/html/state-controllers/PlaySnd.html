Channel = チャンネル番号

型整数
省略時-1

チャンネルを指定。

同じチャンネルのPlaySndが実行されると、それまで鳴っていた音は止まります。StopSndで特定の音を止める場合にも必要。また、チャンネル0は、ボイス再生専用で、再生中にmovetypeがH(やられ)になると、音が停止するという特性を持っています。-1で空いてるチャンネルを使用することになり、再生間隔が短いと、音声がオーバーラップします。キャラ音声の場合は、激しく不自然となるので、忘れずに0を指定しましょう。

value = グループ番号, サウンド番号

省略不可
型整数, 整数
省略時?, ?

再生する音声を指定。

10,1のようにDEFファイルのSoundで指定したSNDファイルに登録されている音声を指定して再生します。

F0,5のようにFをつけるとcommon.sndから共通の音声を再生できます。

F5,0打撃音(弱)
F5,1打撃音(やや弱)
F5,2打撃音(中)
F5,3打撃音(やや強)
F5,4打撃音(強)
F6,0ガード音
F7,0倒れ着地音(弱)
F7,1倒れ着地音(中)
F7,2倒れ着地音(強)
F20,0暗転音

Volume = 音量

型整数
省略時0
最小値-255
最大値255

音量の強弱を調整。

0が標準で、正数だと音が大きく、負数だと小さくなります。

;VolumeScale = 音量

型浮動小数点数
省略時100
最小値0
最大値100

音量を調整。

Version1.0からVolumeがVolumeScaleに変更されました。

100は100%、50は50%になります。0で無音。

LowPriority = 先方優先フラグ

型整数
省略時;LowPriorityが実行されません。

基本的に、同じチャンネルのPlaySndが実行されると、それまで鳴っていた音は止まりますが、lowpriorityを0以外に指定すると、同じチャンネルの音が鳴ってる場合は、PlaySndが実行されなくなります。チャンネルが-1の場合は無効。

FreqMul = 周波数

型浮動小数点数
省略時1.0

周波数を倍数で指定。

1.0で音声に変化はなし、1.0より小さくすると低音、1.0より大きくすると高音になります。

Loop = 繰り返しフラグ

型整数
省略時0

0以外を指定すると、サウンドがループするようになります。BGMを鳴らすときなどに？

Pan = パノラマ位置

型整数
省略時0

音が出る位置を変更します。正で自分の前方、負で後方位置から音が鳴ります。単位はピクセル。

0でプレイヤーの位置から音が鳴ります。

AbsPan = パノラマ位置

型整数
省略時;Panが優先して実行されます。

panとほぼ同じ。panはプレイヤーを基準として位置を指定(正の値が前方、負は後方)しますが、こちらはスクリーンの中央からの位置で指定します。panとの同時指定不可。

IgnoreHitPause = ヒット停止中も処理するか

型0か1
省略時0
最小値0
最大値1

HitPauseTime（ヒット停止）中に、このステートコントローラーを評価・実行するかを指定します。

  • 0（既定）: ヒット停止中は評価されません。
  • 1: ヒット停止中も評価・実行されます。

値は0/1の整数定数のみです（var等の式は使用不可）。

注意: ヒット停止中はIgnoreHitPause=1のステコンだけが実行・内部制限カウントの対象になる挙動が報告されており、通常制作では問題になりませんが、極端な条件下では想定外の挙動が起きる可能性があります。

補足: [StateDef -3]は投げ等で他者のステートデータを使用している間はチェックされないため、IgnoreHitPauseを1にしても走らない局面があります。

IKEMEN GO: ZSSの後方互換性対応や挙動整合のため、IgnoreHitPause周辺はリリース間で修正・拡張が入っています。MUGENと完全一致しないケースもあり得るため、互換性重視のコードは対象ビルドで挙動確認してください。

Persistent = 実行頻度（トリガー成立回数の間引き）

型整数
省略時1
最小値0
最大値128

Persistent は、このステートコントローラーが「実行可能（発火）」になった回数を基準に、実行頻度を間引くための共通パラメーターです。

まず「トリガー成立（= 実行可能）」の定義は次のとおりです。

  • triggerall は共通の前提条件（AND）です。triggerall が偽のフレームでは、trigger1 以降が成立していても発火しません。
  • trigger1 / trigger2 / trigger3 ... は番号ごとにグループで評価されます。
    • 同じ番号（例：trigger1 が複数行）は AND（全部真ならその番号グループが真）。
    • 番号が違うグループ同士（trigger1 と trigger2 など）は OR（どれか1つのグループが真なら発火）。

この「発火（トリガー成立）」が起きた回数に対して、Persistent は次のように動作します。

  • 1（既定）: 発火するたびに毎回実行します。
  • 0: そのステートにいる間は最初の1回だけ実行します（ステートを離れて戻るとカウントはリセットされ、再び1回実行可能になります）。
  • N（2以上）: 発火したN回に1回だけ実行します。
    例：発火が毎フレーム続く（= 毎フレーム発火条件が真）なら、見かけ上はNフレームに1回の実行になります。発火が断続的な場合は、実行間隔も断続的になります（“フレーム”ではなく“発火回数”で数えるため）。

値に指定できるのは整数定数のみです（var/fvar/sysvar を含む式は不可）。

注意: 一部の解析記事では、エンジン内部でステート内のステートコントローラーごとに「Persistent用のカウンタ」が確保され、最大512個相当まで管理される、と説明されています。極端に大量のステートコントローラーを1つのステートに詰め込む設計は、可読性だけでなく実装上の制約にも触れやすいため、常時処理が肥大化している場合は分割・整理を推奨します。
